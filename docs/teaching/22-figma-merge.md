# 22 · 병합 — 두 입력이 어긋나면 판정하지 않고 보고한다

이전: [21-figma-path.md](21-figma-path.md) — 디자인을 검증 계약으로 읽는다

---

## 무엇이 새로운가

노트 21 까지 입력은 하나씩이었습니다 — 기획서(규칙·성공 조건)이거나 Figma
디자인(요소·문구·흐름)이거나. 실무에는 둘 다 있습니다. 그리고 둘은 반드시
어긋납니다 — 기획서는 "이메일을 입력하세요" 인데 디자인은 "아이디를
입력하세요" 인 날이 옵니다.

`prova run --pdf 기획서.pdf --figma-json 응답.json` — 병합 모드입니다.
화면은 이름으로, 요소는 라벨로 짝지어 **기획서의 규칙 + 디자인의 문구·요소·
흐름**을 한 실행에서 검증합니다 (`s1_merge.py`, 순수 함수, LLM 없음).

## 핵심 결정 — 어긋남은 판정이 아니라 발견이다

어긋난 정보로 무엇을 해야 할까요. 세 가지 길이 있었습니다: 기획서를 진실로
삼거나, 디자인을 진실로 삼거나, **아무쪽도 진실로 삼지 않거나.** 셋째를
골랐습니다.

어느 쪽이 맞는지는 도구가 알 수 없습니다 — 그건 기획자와 디자이너가 정할
일입니다. 도구가 한쪽을 골라 검증하면, 골라진 쪽이 틀렸을 때 **틀린 기준으로
구현을 FAIL 시킵니다.** 그래서 어긋난 항목은 판정에서 빼고, 리포트 맨 위에
**"기획↔디자인 불일치 N건"** 상자로 보고합니다. 케이스가 전부 초록이어도 이
상자는 보입니다 — 구현을 고치기 전에 입력끼리의 모순부터 정리해야 하므로.

이 발견은 경고(spec_warnings)와 다른 채널입니다. 경고는 "추출이 덜 됐다",
발견은 "입력이 서로 모순이다" — 성격이 다른 사실을 한 목록에 섞으면 둘 다
묻힙니다(확인하지 않은 것을 따로 세는 coverage 와 같은 원리).

같은 이유로 **디자인에만 있는 요소는 검증에 넣지 않습니다.** 처음 설계는
"정적 대조에 추가" 였는데, e2e 에서 바로 오탐이 났습니다 — 디자인에 OTP
입력란을 그려 두면 기획서를 완벽히 지킨 구현이 "OTP 가 화면에 없다" 로 FAIL
합니다. 구현이 늦은 건지 디자인이 앞서간 건지 판정할 근거가 없으므로,
발견으로만 남깁니다.

## 흐름 채택 규칙 — 실물이 만들어 준 사례

디자인의 prototype 연결도 기획서와 모순일 수 있습니다. 실물 픽스처가
정확히 그랬습니다: 디자이너는 `가입하기 → 로그인` 을 연결했지만, 기획서의
가입 성공 조건은 `/welcome` 으로 갑니다. 이 흐름을 그대로 실행하면 기획서
준수 구현이 FAIL 입니다.

그래서 Figma 흐름은 채택 규칙을 통과한 것만 실행합니다:

    같은 흐름을 기획서도 적었다        -> 이미 검증된다, 접는다
    누르는 요소가 병합 화면에 없다     -> 발견 + 미채택
    누르는 요소가 링크다               -> 순수 이동 — 채택
    버튼(제출형)이다                   -> 출발 화면 성공 조건의 경로와 목적지를
        대조: 일치=채택 · 불일치=발견+미채택 · 경로 없음=판정 불능, 미채택

실물 관통에서 가입하기 흐름은 넷째 규칙의 '불일치' 로 걸려 발견이 됩니다 —
"디자인은 '가입하기' 가 로그인으로 간다고 그렸지만 기획서 성공 조건은
/welcome 로 갑니다." 이게 이 도구가 구현 코드를 한 줄도 보기 전에 잡아낸,
기획과 디자인 사이의 실제 모순입니다.

## 관통 결과 (multi 기획서 + 실물 응답, 2026-08-25)

| 확인 | 결과 |
|---|---|
| good 전 케이스 | **전부 PASS** — 병합해도 오탐 0 |
| 규칙 케이스 | 병합에서도 생성·실행 (기획서 몫) |
| PDF 흐름 (signup_then_login 등) | 병합에서도 돈다 |
| 발견 목록 | 정확히 둘 — 검색 화면이 디자인에 없음 · 가입하기 흐름 모순 |
| 손제작 불일치 응답 | placeholder 어긋남·OTP·비밀번호 누락이 발견으로 실리고, 어긋난 안내 문구는 판정에서 빠진다 |

## 남은 것

- **명시 매핑 override** — 이름이 다른 화면·요소를 사람이 이어 주는 인자.
  필요해지면.
- ~~**웹 UI 병합 지원**~~ — 같은 날 닫음. 작업 콘솔에 Figma 응답 셀렉트가
  생겼고, **계획 화면이 실행 전에 불일치를 보여준다** — 사람이 케이스를
  승인하는 자리가 입력 모순을 보는 자리이기도 해야 한다.
- **3화면 이상 흐름** — 기존 한계 그대로.
