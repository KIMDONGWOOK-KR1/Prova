# 변이 시험 — 정답이 정해진 차이를 기획서에 심어 탐지율 재기 (2026-11-07)

## 왜 쟀는가

실물 기획서는 한 건뿐이고 더 받기 어렵다. 그 한 건에서 잰 탐지율(차이 11건 중 8건)은 표본이
작고, 규칙을 그 문서를 보며 고쳤으므로 그 문서에 맞춰졌을 수 있다. 그래서 **기획서 쪽에 차이를
일부러 심어** 정답이 있는 표본을 늘렸다. 사이트는 그대로 두고 기획서 글자 하나만 바꾸면
"기획서와 사이트가 다르다" 는 상태가 정답과 함께 생긴다.

## 방법

- 대상: 외부 연습 사이트 기획서 다섯 개([external-specs](external-specs/README.md)의 pta_login2·
  herokuapp_login2·saucedemo_login2·ae_search·inventory). 가입 기획서는 실제 계정이 생겨 뺐다.
- 변이 종류: 기획서의 따옴표 문구(성공·실패 문구) 15, UI 요소 표의 라벨(입력·버튼·선택) 15,
  선택지 1, 예시 데이터 값 1 — **32개**. 바꾸는 방법은 영어면 마지막 단어를 `Sample` 로,
  한글이면 뒤에 ` 변경` 을 붙인다. 띄어쓰기만 다른 차이는 결함으로 세지 않기로 했으므로(D4)
  글자를 바꾼다.
- 변이마다 PDF 를 다시 만들어 **S1(실모델 Qwen3.5-4B)부터 끝까지** 돌렸다. VLM(2차 경로)은
  끄고 돌렸다. 기준은 같은 날 원본 기획서로 돌린 실행이다.
- '잡음' = 기준 실행에서 PASS 였던 케이스가 변이 실행에서 FAIL 이 됐다. 분류가
  `assertion_mismatch`·`input_error` 면 **결함으로**, `element_not_found`·`page_error` 등뿐이면
  **실행 문제로** 잡은 것이다.
- 재현: `scripts/mutation_test.py` (plan → run → report). 자동 집계가 '놓침' 으로 센 것은
  사람이 한 번 봐서, 그 변이를 맡는 케이스가 기준 실행에서 이미 FAIL 이면 '잴 수 없음' 으로 옮겼다
  (아래 표에 반영).

변이가 없는 케이스의 판정은 바뀌지 않았다 — 새 FAIL 은 전부 바꾼 문구·라벨을 쓰는 케이스였다.

### 잴 수 없던 6개

| 변이 | 이유 |
|---|---|
| ae_search 3개 | 검색 버튼이 글자 없는 아이콘이라 VLM 없이는 원본부터 전부 FAIL(9월부터 알려진 한계) |
| pta 실패 문구 2개 | 오류 문구가 조작 전부터 숨은 채 화면에 있어 원본부터 `unverifiable`(확인할 수 없음) |
| inventory 예시 상품명 | 이 화면은 정상인데 HTTP 404 를 돌려줘 원본부터 `page_error` |

### 놓친 2개

| 변이 | 왜 놓쳤나 |
|---|---|
| inventory — 빈 아이디 오류 문구 | 이 기획서는 문구를 '실패 조건' 표에만 적고 주어를 "사용자 이름" 이라고 썼다. 라벨은 `Username` 이라 칸과 이어지지 않았고, 필수 케이스는 '오류가 떴는가' 만 본다. 같은 문구를 요소 표에도 적은 saucedemo_login2 에서는 잡았다 |
| inventory — 정렬 설명 속 선택지 이름 | 문구가 "정렬에서 '…' 를 고르면 가격 내림차순" 이라는 설명 문장에만 있다. 정렬 결과를 확인하는 케이스가 없다 |

### '실행 문제로' 잡힌 2개

- saucedemo 상품 목록은 HTTP 404 를 돌려주므로 그 화면의 FAIL 은 전부 `page_error` 로 분류된다(2개).

### 라벨 확인 수정 뒤 다시 잰 것 (2026-11-08, `1a52749`)

처음 측정(11-07)에서는 결함으로 18·실행 문제로 6 이었다. 그때 '실행 문제로' 의 4개는 라벨을 바꾼
변이였는데, 라벨 확인 케이스가 기획서의 안내 문구(placeholder)로 칸을 찾아 '라벨이 있다' 로
세어 PASS 했고, 안내 문구 케이스만 `element_not_found` 로 깨졌다. 라벨 확인이 안내 문구로만 찾은
칸을 라벨로 다시 찾도록 고친 뒤 같은 변이를 replay 로 다시 돌리니 그 4개를 라벨 확인 케이스가
`assertion_mismatch`(결함으로) 로 잡았다. 원본(변이 없는) 판정은 바뀌지 않았고, 실물 기획서
측정(11-09 재측정)의 판정 17개도 그대로다(탐지 8/11·오탐 0).

## 읽는 법·한계

- **사람이 실제로 낸 실수가 아니라 만든 차이다.** 실물 기획서 탐지율(8/11)을 대신하지 않고 보조
  지표로 쓴다.
- 바꾸는 방법이 한 가지(단어 하나를 `Sample` 로)뿐이라 아주 다른 문구로 바뀐 경우만 쟀다. 비슷한
  문구(오타 하나)는 더 어렵다.
- 사이트 다섯 곳, 화면은 로그인·검색·목록이다. 가입·긴 폼은 재지 않았다.
- VLM 을 끈 결과다. 켜면 ae_search 처럼 잴 수 없던 것 일부가 잴 수 있게 된다.
