# 로컬 모델 vs 외부 API — 같은 골든 105항목으로 대조 (2026-11-10)

## 왜 쟀는가

운영 계획서 4-6 의 성과 지표 6 은 '로컬 모델 vs API 비교 — 단계별 정확도 차이' 다. 지금까지는
"로컬로 S1 골든 105/105 를 넘겨 API 가 필요 없었다" 고만 말했고, 실제로 API 를 불러 견준 적이
없었다. GPU 반납(11-13) 전이라 로컬 쪽도 실모델로 다시 잴 수 있을 때 쟀다.

## 방법

- **시험지:** `tests/test_s1_golden.py` 의 105항목. 공개 픽스처 기획서 7개(화면 6개 + 통합 문서 1개)를
  읽혀 손으로 만든 정답(golden)과 대조한다 — 화면 정보·요소·검증 규칙·에러 문구·예시값·시나리오·
  통합 문서의 화면 나누기와 흐름. 모델 호출은 11번이다.
- **같은 것:** 프롬프트, 스키마, PDF 글자 추출, 채점. 백엔드만 바꿨다
  (`PROVA_LLM_BACKEND=vllm | claude`).
- **로컬:** Qwen3.5-4B(AWQ 4bit), CHEETAH A100 MIG 1g.10gb 조각의 vLLM, SSH 터널, temperature 0.
- **API:** Claude Opus 5.5 · Claude Haiku 5.5, Anthropic Messages API, effort `medium`,
  `src/prova/llm/claude_backend.py`. 이 모델들은 temperature 를 받지 않아 보내지 않았다.
- **시간·토큰:** `src/prova/llm/metered.py` 가 호출마다 벽시계 시간과 API 가 돌려준 토큰 수를 센다.
  비용은 그 토큰 수 × 2026-11 공시 단가(Opus 5.5 입력 $4·출력 $20, Haiku 5.5 입력 $0.10·출력 $0.50, 100만 토큰당).
- **실물 기획서는 보내지 않았다.** 외부 API 로 나간 것은 저장소에 공개된 픽스처뿐이다.

- **정확도 차이는 0 이다.** 4B 로컬 모델이 이 시험지에서 가장 큰 API 모델과 같은 답을 낸다.
- **시간은 API 가 빠르다** — Haiku 는 로컬의 약 0.4배, Opus 는 약 0.8배. 로컬 쪽 시간에는
  SSH 터널과 MIG 조각(A100 의 1/7) 이라는 조건이 들어 있다.
- **비용은 Haiku 면 무시할 수준, Opus 면 화면 하나에 약 $0.09** 다. 입력이 호출당 약 1만 7천
  토큰인 것은 추출 프롬프트(규칙과 예시)가 길어서다.

## 해석 — 무엇을 말하고 무엇을 말하지 못하는가

- 이 프로젝트가 로컬 모델을 고른 이유는 정확도가 아니라 **자료가 밖으로 나가지 않는 것**이다
  (10-16 멘토링: 기업은 계정·보안 자료를 외부 생성형 AI 에 올리지 못한다). 이 측정은 그 선택이
  **정확도를 내주고 산 것이 아님**을 보인다 — 적어도 이 시험지에서는.
- **천장 효과가 있다.** 골든 105항목은 로컬 모델이 전부 맞히도록 프롬프트를 다듬어 온 시험지다.
  셋 다 만점이라 '누가 더 나은가' 는 여기서 갈리지 않는다. 로컬이 놓치는 곳은 실물 기획서(엄격
  82.2%, 45개 중 8개 놓침)에 있는데, 그 문서는 유출 금지라 외부 API 로 보낼 수 없다 — 그래서
  **API 가 실물에서 더 잘 읽는지는 이 측정으로 알 수 없다.**
- 잰 것은 S1(기획서 읽기)뿐이다. S3 요소 탐지(2차 경로, 화면 이미지)는 비교하지 않았다.
- API 쪽은 한 번씩만 돌렸다. temperature 를 고정할 수 없어 반복 실행의 흔들림은 재지 않았다.

## 재는 중에 찾은 것

**Claude 의 정형 출력은 키를 미리 정하지 않은 객체를 받지 못한다.** S1 스키마의 `constraints`
(검증 규칙), `given`, 씨앗 표의 행이 그런 자리다. SDK 의 스키마 변환은 이를 오류 없이 '속성 없는
닫힌 객체' 로 바꾸고, 모델은 **항상 `{}` 를 낸다.** 첫 실행에서 Haiku 가 97/105 였는데 틀린 8개가
전부 '검증 규칙이 비었다' 였다 — 모델이 아니라 백엔드의 결함이었다. 그 자리를 JSON 문자열로
주고받게 고친 뒤(`_stringify_free_form`·`_restore_free_form`) 105/105 가 됐다.

vLLM 의 `guided_json` 이 조용히 무시되던 것(노트 02)과 같은 모양이다: **스키마가 걸렸는지는
오류가 아니라 결과로만 드러난다.** 백엔드를 바꿀 때 골든 대조를 먼저 돌려야 하는 이유다.
네트워크 없는 확인은 `tests/test_claude_backend.py`.

## 다시 재기

    # 로컬 (터널이 열려 있어야 한다)
    PROVA_LLM_BACKEND=vllm PROVA_LLM_USAGE_OUT=runs/api-compare/usage_local.json \
      uv run pytest tests/test_s1_golden.py -q

    # API (ANTHROPIC_API_KEY 필요, 과금된다)
    PROVA_LLM_BACKEND=claude PROVA_CLAUDE_MODEL=claude-haiku-5-5 \
      PROVA_LLM_USAGE_OUT=runs/api-compare/usage_haiku.json \
      uv run pytest tests/test_s1_golden.py -q

Claude 백엔드는 **제품 입구(CLI `--backend`, 웹 UI)에 붙이지 않았다.** 기획서를 실수로 외부에
보내는 길을 만들지 않기 위해서다. 측정용 환경 변수로만 켜진다.
