# 우리가 안 만든 웹앱 세 곳 — 실물 7B 관통 (2026-09-23)

## 왜 쟀는가

지금까지 Prova 가 검증한 대상은 **전부 우리가 만든 SUT** 였다. 도구와 대상을 같은 사람이
만들면, 대상의 마크업이 모르는 사이에 도구에 맞춰진다 — 도구가 못 다루는 모양은 애초에
SUT 에 들어가지 않는다. 실물 기획서를 기다리는 동안 '실물 대상' 쪽 절반을 먼저 확인했다.

## 무엇을 쟀는가

| 사이트 | 화면 | 우리 SUT 에 없던 모양 |
|---|---|---|
| practicetestautomation.com | `/practice-test-login/` | 페이지가 자기 테스트 케이스와 기대 문구를 **화면에 공개**한다. 오류 칸이 문구를 든 채 늘 DOM 에 있다 |
| the-internet.herokuapp.com | `/login` | 로그인 버튼 글자가 `<i class="fa ...">` 안에 있다(Font Awesome 아이콘) |
| www.saucedemo.com | `/` | React SPA. `<label>` 이 없고 `aria-label`·placeholder·`data-test` 만 있다. 폼에 `aria-label="Login"` |

기획서는 사이트가 **공개한 동작만** 옮겨 적었다(계정·문구·이동 경로). 기대값을 우리가
지어내지 않는다. S1 은 CHEETAH 의 실물 Qwen2.5-7B-AWQ, 요소 탐지는 1차 경로(VLM 없음).
기획서·리포트는 저장소에 넣지 않았다 — 외부 사이트는 바뀔 수 있어서, 드러난 **모양**을
`set_content`·`page.route` 로 떼어 테스트에 고정했다.

## 결과

| 사이트 | 첫 실행 | 원인 | 고친 뒤 |
|---|---|---|---|
| practicetestautomation | 1P / 1F | 테스트 계정 표의 열 제목이 라벨과 달라 정상 케이스가 **지어낸 값**으로 로그인 → FAIL('기획서와 다름'). 예시 동작 표도 조용히 빠져 음성 케이스 0건. 표를 맞추자 4/4 PASS 였는데 그중 1건은 **빈 통과**(아래 3) | 2 PASS · 2 **확인 불가** |
| the-internet | 1P / 1F (표 맞춘 뒤 1P / 3F) | 버튼 이름이 `" Login"` — 아이콘 글리프가 앞에 붙어 정확 일치 role 조회 0개 → '기획서의 유형(버튼)과 구현이 다르다' | **4 / 4 PASS** |
| saucedemo | 3P / 2F (표 맞춘 뒤 2P / 5F) | 'Login' 을 label 전략이 `<form aria-label="Login">` 으로 잡아 **폼을 클릭** → 제출 안 됨. 첫 실행의 정상 로그인 PASS 는 로그인하지 않고 통과한 것(아래 4) | **7 / 7 PASS** |

**첫 실행의 실패는 전부 '기획서와 다름'(구현 결함)으로 분류됐다. 세 사이트 모두 정상
동작하는 공개 사이트다 — 전부 없는 결함을 보고한 오탐이었다.** 그리고 통과 중 둘은
아무것도 확인하지 않은 통과였다.

## 찾은 결함과 고친 방법

| # | 모양 | 무엇이 잘못됐나 | 고친 곳 |
|---|---|---|---|
| 1 | 같은 이름의 폼 안에 버튼 | label 전략이 먼저 돌아 폼을 잡음 | 버튼·링크는 role → text 만 (`dom_locator._CLICKABLE_TYPES`) |
| 2 | 아이콘 폰트가 붙은 버튼 | 사설 영역 문자(U+E000–U+F8FF)가 접근성 이름에 포함 | 이름 비교에서 그 글자와 앞뒤 공백만 무시 (`_role_name`) — 부분 일치로 넓히지 않음 |
| 3 | 조작 전부터 화면에 있는 문구 | 숨은 오류 칸·안내문의 글자로 통과 | 첫 이동 직후 기준선을 읽고, 같은 화면에서 그 문구에만 기댄 통과는 **확인 불가**(`unverifiable`) |
| 4 | 성공 조건을 모델이 의역 | 경로·문구가 빠져 '에러 없음' 만 보고 통과 | 본문의 '성공 조건' 절에서 다시 읽기, 그래도 없으면 **약한 확인** 표시 |
| 5 | 표 열 제목 ≠ 라벨 | 테스트 계정·예시 표가 조용히 빠짐 | 대소문자·공백·요소 ID 까지 허용, 못 읽으면 경고 두 종 |
| 6 | 모델이 실패 조건 표를 의역 | '모델 메모' 경고 네 줄(판정 무관) | 남음 |

PTA 의 '확인 불가' 두 건은 정답이다. 그 페이지는 연습 문제 목록에 `Verify error message
text is Your username is invalid!` 처럼 기대 문구를 화면에 늘 보여 준다. 그 문구로는
로그인이 실패했는지 확인할 수 없다 — 통과로 두면 거짓이고 결함으로 두면 오탐이다.

## 우리 SUT 에서 드러난 것

4 를 고치자 **비밀번호 찾기 화면의 정상 케이스가 원래 약한 확인이었다**는 것이 드러났다.
골든의 성공 조건에 인용부호가 없어('재설정 메일을 보냈습니다.') 문구를 확인하지 않고
'에러 없음' 으로 통과하고 있었다. 실물 7B 도 인용부호를 빠뜨리는데, 이제 본문에서 다시
읽어 그 문구까지 확인한다. 판정 수는 그대로(good 9/9, bad 7P/2F).

## 한계

- 사이트 세 곳, 로그인 화면만이다. 회원가입·검색·표 화면은 재지 않았다.
- 4 의 백필은 saucedemo 재실행 세 번에서는 쓰이지 않았다 — 그때는 모델이 스스로 성공 조건을
  뽑았다(첫 실행의 누락은 모델 변동). 실물 발동은 비밀번호 찾기 화면에서 확인했다.
- 외부 사이트는 바뀐다. 회귀 확인은 사이트가 아니라 고정한 모양으로 한다
  (`tests/test_real_site_shapes.py`·`test_baseline_capture.py`·`test_table_header_match.py`·
  `test_success_backfill.py`).
