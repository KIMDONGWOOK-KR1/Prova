## 처음 재니 79.1% 였다

이 지표는 "기능은 다 들어가 있다" 고 여겨져 측정 문서 없이 지나가 있었다.
실제로 재니 이랬다.

| 필드 | 첫 측정 |
|---|---:|
| 실행 로그 | 100.0% |
| **입력 데이터** | **0.0%** (0/166) |
| 기대 결과 | 100.0% |
| 실제 결과 | 100.0% |
| 실패 원인 | 100.0% |
| **전체** | **79.1%** |

**입력 데이터가 리포트에 하나도 없었다.** `TestStep.value` 는 있고
`playwright_driver` 가 그 값으로 입력까지 하는데, `StepResult` 에 `value` 필드가
없어서 결과로 넘어가지 않았다. 의도적으로 뺀 것이라는 기록도 없었다 —
문서에도 코드 주석에도.

이것이 왜 문제인가. 개발자가 FAIL 을 보고 가장 먼저 하는 일은 **같은 값을 손으로
넣어 보는 것**이다. 리포트에 무엇을 넣었는지가 없으면 그걸 할 수 없다. 케이스
제목에 값이 적히는 경우가 있어(`입력값 'Aa1!aaa'`) 눈으로는 가려져 있었다 —
제목은 사람이 읽는 문장이고 기계가 집계할 수 있는 필드가 아니다.

고친 것은 셋이다.

- `models.py` — `StepResult.value` 추가
- `s4_executor/playwright_driver.py` — 실행한 값을 결과에 담는다
- `s6_report/report_builder.py` — 스텝 표에 '입력값' 열을 낸다 (JSON 에만 있으면
  사람이 리포트를 열어 볼 때는 여전히 안 보인다)

## 그리고 96.0% 에서 한 번 더 걸렸다

고친 뒤 재니 96.0% 였다. 남은 32 건이 전부 `*-required-*` 케이스였다.

**빈 문자열을 '값 없음' 으로 세고 있었다.** 필수 입력 검증 케이스가 넣는 값이
정확히 빈 문자열이다 — 아무것도 넣지 않은 상태를 만드는 것이 그 케이스의 일이다.
빈 문자열을 누락으로 세면 그 케이스들이 통째로 빠진다.

여기서 보는 것은 **'무엇을 넣었는지가 기록됐는가'** 이지 '값이 비어 있지 않은가'
가 아니다. 채점기를 고쳤다 — `value is not None` 으로 본다. `''`(넣었다)과
`None`(기록이 없다)은 다른 사실이고, 그 구분을 테스트가 지킨다.

리포트 HTML 도 빈 값을 `''` 로 보인다. 칸이 비어 있으면 '안 넣었다' 인지
'기록이 없다' 인지 읽는 사람이 알 수 없다.

## 채점기가 나쁜 소식을 낼 수 있는가

목표가 100% 인 지표는 **늘 100% 를 내는 채점기**와 눈으로 구분되지 않는다.
둘 다 초록불이다.

그래서 채점 로직(`check_case`)을 파일 입출력과 분리해 순수 함수로 두고, 일부러
필드를 뺀 가짜 리포트로 점수가 실제로 내려가는지 테스트한다
(`tests/test_report_completeness.py`, 17건). `scripts/eval_selector_speed.py` 가
오탐 집계에 둔 장치와 같다.

실제로 이 장치가 두 번 일했다 — 위의 79.1% 와 96.0% 가 모두 채점기가 낸
나쁜 소식이다.

## 해당 없음(n/a)을 분모에서 뺀다

케이스마다 다섯이 다 필요한 것은 아니다.

- **입력 데이터** 는 입력 스텝(`fill`·`select`·`type`)이 있는 케이스에만. 화면을
  열어 보기만 하는 케이스(196 중 30)에는 입력이 없다.
- **실패 원인** 은 FAIL 에만 (196 중 39).

없는 것을 누락으로 세면 통과율이 **케이스 구성과 실패 비율을 따라 움직인다** —
리포트를 고치지 않아도 숫자가 변한다. 그건 리포트 완결성이 아니다.
