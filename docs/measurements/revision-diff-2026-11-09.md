# 기획서 개정판 비교 — 변이 기획서 쌍으로 잰 것 (2026-11-09)

`prova diff-spec` / `prova run --since` 가 쓰는 비교(`prova.spec_revision.diff_revisions`)가
두 판의 차이를 제대로 내는지, 바꾸지 않은 것을 바뀐 것으로 말하지 않는지 쟀다.

## 방법

- 표본: [변이 시험](mutation-2026-11-07.md)에서 만든 기획서 쌍 32개(원본 ↔ 글자 하나 바꾼 판).
  외부 연습 사이트 기획서 다섯 개, 문구 15·라벨 15·선택지 1·예시 데이터 1.
- 두 판을 **실모델(Qwen3.5-4B) 추출 결과**로 비교했다. 11-07 변이 시험 때 받은 응답을
  replay 로 다시 썼으므로 모델 서버 없이 같은 결과가 나온다.
- 셌던 것: 심은 차이가 목록에 나오는가, 심은 것과 무관한 줄이 섞이는가.

## 결과

| | 개수 |
|---|---|
| 변이 | 32 |
| 심은 차이가 바뀐 값과 함께 목록에 나옴 | 30 |
| 바뀐 곳은 나오지만 값은 모델이 빠뜨림 (inventory msg03 — 바뀐 문장을 통째로 안 옮겨 적음) | 1 |
| 비교 대상이 아님 (inventory seed09 — 예시 데이터 값) | 1 |
| 심은 것과 무관한 줄이 섞인 변이 | 3 |

무관한 줄 셋:

- saucedemo 라벨 변이 2개 — 라벨이 바뀌자 그 칸에 붙던 '빈 칸 문구' 가 떨어졌다. 빈 칸 문구는
  코드가 라벨로 찾아 붙이므로(`extractor._apply_declared_element_required`) 추출 결과가 실제로
  달라진 것이다. 라벨 변경에 따라온 차이다.
- inventory seed09 1개 — 모델이 성공 조건의 마지막 문장을 빠뜨려 옮겨 적었다. **진짜 헛 변경은
  이것 하나다.**

## 고친 것 — 문장 칸은 따옴표 문구와 경로로 비교

처음에는 무관한 줄이 섞인 변이가 **12개**였다. 거의 전부 모델이 성공·실패 조건 문장을 조금씩
다르게 옮겨 적은 것이었다("문구를 노출한다" ↔ "문구 노출", "이동하지 않음" 을 빼고 적음).
성공 조건·실패 조건은 따옴표 안 문구와 경로(`/...`)만 비교하도록 고친 뒤 3개로 줄었다.
따옴표 문구·경로가 하나도 없는 문장은 공백·구두점만 빼고 글자로 비교한다.

## 읽는 법·한계

- 비교는 **모델이 읽은 결과끼리**다. 같은 문장을 다르게 읽으면 차이로 보인다. 그래서 출력과
  리포트가 "원문과 대조하세요" 를 붙인다.
- 요소는 ID, 없으면 라벨로 짝을 맞춘다. ID 와 라벨이 함께 바뀐 요소는 '없어짐 + 새로 생김'
  으로 보인다.
- 예시 데이터(테스트 계정·상품 목록 값)는 비교하지 않는다.
- 재현: `--backend replay` 와 변이 작업 폴더의 캐시로 `diff_revisions(원본, 변이)` 를 돌린다
  (작업 폴더는 저장소 밖).
