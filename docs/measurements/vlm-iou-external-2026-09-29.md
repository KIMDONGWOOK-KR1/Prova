# 2차 경로 탐지 정확도 — 우리가 안 만든 화면 (2026-09-29)

## 왜 쟀는가

모델 교체(2026-09-28, [model-compare-qwen35-4b-2026-09-28.md](model-compare-qwen35-4b-2026-09-28.md))의
근거는 탐지 성공률 57→81%, 없는 것을 있다고 한 비율 71→7% 였다. 그 시험지(`fixtures/iou`,
18장 · 77항목)는 전부 **우리 SUT 화면**이다 — 우리가 만든 마크업이라 깔끔하고 모양이 비슷하다.
실물 사이트의 광고, 아이콘만 있는 버튼, 촘촘한 폼, 영어 라벨에서도 그 숫자가 유지되는지 봤다.

## 방법

- 스파이크 1~3 에서 도구를 돌려 본 7곳의 11장 · 60항목(있음 40 · 없음 20).
  `scripts/build_iou_external.py` 가 정답표이고, 시험지(그림)는 `runs/iou-external/` 에
  굳혔다 — 남의 사이트 그림이라 저장소에 넣지 않는다. 채점은 SUT 시험지와 같은
  `scripts/eval_vlm_iou.py --dataset runs/iou-external/dataset.json`.
- 정답은 손으로 적은 selector 로 쟀고, 없는 요소는 selector 가 0개로 풀리는 것을 확인한 뒤 넣었다.
- 라벨은 사이트가 보여 주는 말 그대로(영어) 물었다.
- 모델 `qwen3.5-4b-awq` · 시험지 `e173d14c4550` · 굳힌 시각 2026-09-29 16:37 · IoU 문턱값 0.5 · 신뢰도 문턱값 0.5.

## 틀린 6건

| 화면 | 요소 | 무엇을 가리켰나 | 모양 |
|---|---|---|---|
| parabank 회원가입 | Username (입력) | 왼쪽 로그인 패널의 Username 칸 | **같은 이름의 다른 요소** |
| parabank 회원가입 | Password (입력) | 왼쪽 로그인 패널의 Password 칸 | **같은 이름의 다른 요소** |
| saucedemo 상품 목록 | Products (목록) | 같은 글자의 제목 | 같은 이름의 다른 요소 |
| demoqa 웹 표 | Web Tables (목록) | 같은 글자의 사이드바 메뉴 | 같은 이름의 다른 요소 |
| the-internet 표 | Example 1 (목록) | 표 + 제목 (IoU 0.48, 중심 맞음) | 상자 크기 |
| saucedemo 로그인 에러 | 에러 문구 (문구) | 문구 줄 일부 (IoU 0.40, 중심 맞음) | 상자 크기 |

**위험한 것은 parabank 두 건이다.** 입력란이라 파이프라인이 좌표로 값을 넣는 종류이고,
정체 대조(`_require_actionable`)로 막히지 않는다 — 정체 대조는 좌표 아래 요소의 이름이
**기획서의 다른 요소**와 같을 때만 막는데, 여기서는 이름이 찾던 라벨과 **같다**(둘 다
'Username'). 2차 경로가 이 칸을 찾게 되면 회원가입 폼이 아니라 로그인 패널에 값을 넣고,
그 뒤의 판정이 거짓이 된다. SUT 시험지에는 같은 이름의 요소가 한 화면에 둘 있는 모양이
없어서 드러나지 않았다.

목록 두 건(Products·Web Tables)은 지금은 영향이 없다 — 목록은 좌표로 조작하지 않는다.

## 시험지를 만들며 고친 것

- **정답표의 잘못 1건.** the-internet 표 화면에 'Delete 버튼은 없음' 을 넣었는데, 표 안에
  delete **링크**가 보인다. selector(`button`)는 0개였지만 그림에는 그 말이 있었다. 첫
  채점에서 모델이 그 링크를 가리켜 오탐 1건(5.0%)으로 셌고, 틀린 것은 정답표였다. 'Submit'
  으로 바꾸고 다시 굳혔다. '없음' 항목은 selector 만이 아니라 **그림에 그 말이 없는지**도
  봐야 한다.
- **같은 그림 1장 제외.** practicetestautomation 의 로그인 에러 화면은 에러 문구가 보이는
  화면 아래(y≈812)에 떠서 첫 진입과 같은 그림이 찍혔다. 넣으면 점수만 부풀린다.

## 한계

- **표본이 작다.** 40항목에서 한 건이 2.5%p 다. SUT 시험지보다 높게 나온 것을 '외부에서 더
  잘한다' 로 읽으면 안 된다 — 말할 수 있는 것은 '떨어지지 않았다' 까지다.
- **보이는 화면 밖은 잴 수 없다.** 2차 경로는 보이는 화면(1280×800)만 모델에 준다
  (`heal_with_vlm` 의 `page.screenshot()`). expandtesting 회원가입 폼은 위쪽 광고의 높이에
  따라 화면 안팎을 오갔다 — 같은 날 세 번 굳혀 화면 밖 항목이 4 · 0 · 1개였다. 화면 밖
  요소는 2차 경로가 **아예 볼 수 없다**. 이번 시험지에서는 Register 버튼 1개가 그랬다.
- **그날의 화면이다.** 광고와 사이트가 바뀐다. 다시 재려면 굳히기부터 다시 한다
  (`dataset_id` 가 달라진다).
- 한 번 채점했다. temperature 0 이지만 서버를 다시 띄우면 경계 항목이 움직일 수 있다
  (모델 비교 측정의 관측).

## 다음에 할 일 (제안)

1. **같은 이름의 요소가 둘 이상인 화면에서 2차 경로를 쓰지 않는다.** 1차 경로가 같은 라벨의
   후보를 둘 이상 봤다면 2차 경로도 그중 하나를 고를 근거가 없다 — '후보가 정확히 하나일
   때만 답한다' 는 원칙을 2차 경로에도 적용한다. 좌표 아래 요소가 같은 라벨의 후보 중 무엇인지
   확인하는 방법도 있다.
2. 보이는 화면 밖 요소: 2차 경로를 부르기 전에 스크롤할지는 실물 기획서를 본 뒤 정한다 —
   어디로 스크롤할지 모르는 채 스크롤하면 찍히는 그림이 실행마다 달라진다.
