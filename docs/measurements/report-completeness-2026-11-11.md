## 어떻게 쟀나

- **표본:** 픽스처 기획서 10개 × SUT 변형 12종 = 120 실행, 2,484 케이스(실패 1,525·통과 959).
  표본을 뽑지 않고 실패 케이스 전부를 셌다.
- **실행:** `scripts/dump_verdicts.py … --every-step` — 스텝마다 스크린샷·DOM 을 남기는 제품 기본
  설정. LLM 은 mock(저장된 추출 결과)이라 GPU 가 필요 없다. 리포트를 만드는 S2~S6 은 실제 코드다.
- **채점:** `scripts/score_report_completeness.py` 가 실행 폴더의 `report.json` 을 읽는다.
  HTML·엑셀은 같은 자료로 그려진다(엑셀은 시트의 칸을 직접 열어 따로 확인했다).

| 칸 | 찼다고 친 조건 |
|---|---|
| 실행 로그 | 스텝 기록이 한 줄 이상 있고 줄마다 동작·결과가 있다 |
| 입력 데이터 | 입력·선택 스텝마다 넣은 값이 적혀 있다. 빈 칸으로 둔 입력은 빈 글자로 적힌다 |
| 기대 결과 | '기대' 문장이 있다 |
| 실제 결과 | '실제' 문장과 최종 URL 이 있다 |
| 실패 원인 | 실패 분류와 사유 문장이 있다 |

## 읽을 때 주의할 것

- **칸이 '있는가' 를 센 것이지 '쓸 만한가' 를 잰 것이 아니다.** 문장이 읽는 사람에게 충분한지는
  사람이 봐야 한다. 실패 분류마다 가장 흔한 문장을 눈으로 확인한 정도다(예: 기획서와 다름 —
  "다른 문구가 노출됨: '로그인 정보를 확인해주세요.'", 페이지 오류 — "스텝 1(navigate …) 실패:
  HTTP 404 — …"). 페이지 오류의 '실제' 줄은 "스텝 1 에서 중단" 으로 짧고, 내용은 사유 문장에 있다.
- **실패의 76%(1,158건)는 페이지 오류다.** 기획서의 화면이 없는 변형에 돌린 조합(예: 로그인 기획서
  × 표 변형)이 첫 이동에서 404 로 멈춘 것이다. 이 케이스들은 입력 스텝까지 가지 못해 '입력 데이터' 가
  해당 없음이다. **넣은 값이 실제로 기록됐는지 확인된 실패 케이스는 445건**(입력·선택 스텝 955개,
  그중 빈 칸으로 둔 입력 16개)이고 모두 값이 적혀 있다.
- **중간에 멈춘 케이스는 실행한 스텝까지만 적힌다.** 실행하지 않은 뒤 스텝의 값은 리포트에 없다 —
  넣지 않은 값이므로 빈 칸으로 세지 않았다.
- **픽스처 기획서와 SUT 에서 잰 수치다.** 실물 기획서의 실행은 세지 않았다. 다섯 칸은 판정 코드가
  채우므로 기획서에 따라 달라질 여지는 작지만, '기획서 근거' 가 붙는 비율은 기획서의 꼴(요소 표가
  있는가)에 따라 달라진다.
- 2026-11-10 전에는 단계 표에 넣은 값이 없었다(`StepResult.value` 를 그날 더했다). 그 전 코드로
  만든 리포트는 '입력 데이터' 칸이 비어 이 수치가 나오지 않는다.
