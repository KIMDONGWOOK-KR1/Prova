## 이 변경이 답하는 질문

`placeholder` 필드는 `models.py` 에 **처음부터 있었습니다.** 그런데 S3 의 요소 탐지
폴백으로만 쓰였습니다 — 라벨로 못 찾으면 placeholder 로 찾아보는 용도.

즉 **기획서가 안내 문구를 적을 자리가 없었고, 구현의 안내 문구는 아무도 확인하지
않았습니다.** '아이디를 입력하세요' 로 바뀌어도 전 케이스가 통과했습니다.

안내 문구는 사용자가 화면에서 **가장 먼저 읽는 글자**입니다. 그게 기획서 관할 밖에 있었습니다.

> **필드가 있다는 것과 그 값이 검증된다는 것은 별개다.**

모델에 자리가 있는 것을 '다루고 있다' 로 착각하기 쉽습니다. 이 PR 에서 두 번 그랬습니다.

## 무엇을 했나

기획서 요소 표에 **`안내 문구` 열**을 추가하고, 화면당 케이스 한 건으로 대조합니다.

```
| 요소 ID | 유형 | 라벨 | 필수 | 입력 검증 규칙 | 안내 문구 | 에러 메시지 |
                                              ^^^^^^^^^ 새로 추가
```

- `declared_placeholders()` — 표에서 결정적으로 읽습니다(LLM 을 쓰지 않습니다)
- `read_placeholders()` — 화면에서 실제 `placeholder` 속성을 읽습니다
- `placeholders_match` — 판정

스텝은 `navigate` 하나뿐입니다. 안내 문구는 입력 **전에** 보이는 글자이므로 채우고
제출할 이유가 없습니다 — 오히려 값을 채우면 placeholder 가 가려집니다.

## 열 하나를 더한 것이 이미 있던 버그를 드러냈습니다

**이게 이 커밋에서 가장 값진 부분입니다.**

열을 추가하니 표가 넓어져서 회원가입 요소 표의 마지막 행(`로그인하러 가기`)이 **다음
페이지로 밀렸습니다.** PDF 는 표가 페이지를 넘어가면 헤더를 다시 그리고, pdfplumber 는
그것을 **별개의 표 두 개**로 읽습니다.

`_element_table()` 이 첫 표만 돌려줘서 그 행이 사라졌습니다. 그러면

- 프롬프트에도 그 요소가 안 들어가고
- 행 누락 경고도 안 뜹니다 (`declared_element_ids` 가 그 요소를 모르니까)

**행을 빠뜨리지 않기 위해 만든 장치가 같은 이유로 무력해진 것입니다.**

헤더가 같은 표만 이어 붙이도록 고쳤습니다. 다른 표를 잘못 붙이면 없는 요소를
만들어내므로 헤더 일치를 조건으로 뒀습니다.

**이건 제가 만든 버그가 아니라 요소가 많은 실물 기획서에서 먼저 터질 버그였습니다.**
픽스처를 실물에 가깝게 만드는 것 자체가 검증이라는 걸 여기서 배웠습니다.

## 리뷰에서 봐 주면 좋은 판단

### 표에 없는 라벨은 건드리지 않습니다

```python
def _apply_declared_placeholders(spec, declared) -> None:
    for element in spec.elements:
        want = declared.get(element.label)
        if want is None or want == element.placeholder:
            continue      # 표에 없는 요소는 그대로 둔다
```

기획서가 안내 문구를 적지 않은 요소(버튼 등)까지 지우면, 실물 기획서가 그 열을 쓰지 않을
때 LLM 이 본문에서 읽어낸 값을 잃습니다.

### 심은 결함

`bad` 의 로그인 화면 안내 문구를 `'아이디를 입력하세요'` 로 바꿔 뒀습니다(B4). 이 커밋
전에는 아무 케이스도 이걸 보지 못했습니다.
