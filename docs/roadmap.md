# 아직 안 한 것

> 루트 [README.md](../README.md) 에서 갈라져 나온 문서다. 이미 내린 판단은 [design-decisions.md](design-decisions.md).

명세서 §0-2 의 **1차 범위는 닫혔다** — 6단계 파이프라인과 네 화면(로그인·회원가입·검색·
비밀번호 찾기), 그리고 입력 검증 규칙 확인. 2차 항목 세 가지 — **Self-Healing
재탐색**(VLM), **실패 원인 자동 분류**(규칙 기반), **대상 확장**(상품등록·주문조회 —
전제 상태와 자기일관 판정, 2026-08-20 실모델 관통) — 도 끝났다.

계획서 1차 목표 네 개도 모두 닫혔다. 마지막이던 **자연어 → 테스트 시나리오 변환**은
`--request` 와 `prova serve` 로 붙였고, 해석이 결함을 덮지 못하게 하는 네 가지 장치를
함께 넣었다([설계 판단 14](design-decisions.md)).

남은 것을 값 순서로 적는다.

### GPU 제약 — 실측으로 확정됐다

착수 전에는 추정이었고 이제 실측값이 있다.

```
MIG 1g.10gb 파티션    9.50 GiB
7B (UTIL=0.90)        8.30 GiB 사용
남는 것               1.20 GiB
Qwen2.5-VL-3B-AWQ     3.17 GiB (가중치만)
```

**동시 적재는 불가능하다.** 7B 의 `UTIL` 을 최소선까지 낮춰도 가중치를 겨우 덮는 정도다.

그런데 파이프라인을 보면 **LLM 과 VLM 이 동시에 필요한 시점이 없다** — LLM 은 S1,
VLM 은 S3 다. 그래서 시간을 나눠 쓰고, 그 방식으로 S3 정확도를 측정했다(77개 채점, 적중 90.5%).
한 실행에서 둘을 잇는 것은 2026-08-26 에 닫혔다 — `--plan-only` 로 계획을 저장하고
서버를 교체한 뒤 `--resume` 으로 이어 돈다(위 표의 닫힘 행, 노트 23).
