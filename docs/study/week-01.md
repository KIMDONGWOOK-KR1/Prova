## 팀장 시연 대본 (15분)

미리 터미널 두 개를 열어 두고 시작한다.

### 준비 — 시작 전에

```powershell
# 터미널 1. 켜 두고 끄지 않는다
uv run uvicorn sut.app:app --port 8100 --reload --reload-dir sut
```

브라우저로 `http://localhost:8100` 을 열어 **good 과 bad 를 눈으로 먼저 보여준다.**
*"둘 중 어느 쪽이 검사를 빼먹었을까요?"* — 못 맞힌다. **그게 오늘의 요점이다.**

### 1. 착한 쪽 (3분)

```powershell
uv run prova run --pdf fixtures/specs/login_spec.pdf --url http://localhost:8100/good --backend mock
```

→ **10 / 10 PASS.** *"멀쩡한 걸 문제라고 하지 않았습니다. 이게 먼저 확인돼야 해요."*

### 2. 장난꾸러기 쪽 (4분)

```powershell
uv run prova run --pdf fixtures/specs/login_spec.pdf --url http://localhost:8100/bad --backend mock
```

→ **4 PASS / 6 FAIL.** 실패 목록을 소리 내어 읽는다. FAIL 한 줄을 짚으며
*"만든 사람은 이 한 줄만 보고 어느 코드를 고칠지 압니다."*

### 3. 눈으로 보기 (5분)

```powershell
uv run prova run --pdf fixtures/specs/login_spec.pdf `
  --url http://localhost:8100/bad `
  --only require_uppercase --headed --slow 500
```

브라우저 창이 떠서 **스스로 타이핑하고 누른다.** 여기서 웃는다. 이 장면이 1회차에서
가장 오래 기억에 남는다.

### 4. 리포트 열기 (3분)

```powershell
start runs\<run-id>\report.html
```

good 과 bad 를 **나란히 띄워** 놓고 넘어간다.

## 실측 기준값 (2026-09-14 확인)

**이 표의 숫자만 쓴다.** 옛 데모(`runs/demo-*`, 2026-08-16)에서 옮기지 않는다.

| | 결과 |
|---|---|
| `good` | **10 / 10 PASS** · 오탐 0 |
| `bad` | **4 PASS / 6 FAIL** |

`bad` 에 심어 둔 결함은 **4개**인데 FAIL 은 **6건**이다.

| 심은 결함 | FAIL |
|---|---|
| B1 비밀번호 복잡도 검증을 통째로 빼먹음 | **3건** (최소길이·대문자·특수문자) |
| B2 이메일 형식 검증 누락 | 1건 |
| B3 미등록 계정 에러 문구가 기획서와 다름 | 1건 |
| B4 안내 문구가 다름 (`아이디를 입력하세요`) | 1건 |

> **주의 — 저장소 문서와 어긋나는 곳.** `sut/app.py` 첫머리 표는 "심은 결함의 전수" 를
> 자처하는데 **B4 가 빠져 있고**, 4건이 되는 이유를 "B3 가 두 경로에 잡힘" 으로 적어
> 뒀다. 실제로는 B4(`sut/templates/login.html` 주석에 있다)가 별개 결함이다.
> 학생에게는 위 표를 쓰고, 표 수정은 SW팀에 넘긴다.

## 오늘의 핵심 질문 — "4개인데 왜 6건?"

여기에 5분을 쓴다. 먼저 학생에게 묻고 기다린다.

**답.** 비밀번호 복잡도 검사가 코드 한 곳에 모여 있었다. 그 한 곳이 빠지니
**길이·대문자·특수문자 세 규칙이 함께 무너졌다.**

**이어서 물을 것** — *"그럼 세 규칙을 한 번에 검사하는 문제를 냈으면 어땠을까요?"*
→ 길이에서 먼저 걸려 에러가 뜨고, **대문자 검사가 없다는 사실이 가려진다.**
그래서 **규칙 하나마다 문제를 따로 낸다.** (4주차 예고 — 여기까지만)

## 손 실습 (20분)

학생 노트북에서. `uv sync --extra dev` 만 되어 있으면 된다.

```powershell
uv run python
```

```python
import json
r = json.load(open("docs/study/samples/login-bad.report.json", encoding="utf-8"))
print(r["summary"]["pass"], "통과 /", r["summary"]["fail"], "실패")

for c in r["cases"]:
    print(c["verdict"], "|", c["title"])
```

`login-good.report.json` 으로도 한 번. 두 파일은 **저장소에 함께 온다** — 시연에서
만든 `runs/` 는 팀장 노트북에만 있고 `.gitignore` 대상이라 학생에게는 없다.
두 표본은 2026-09-14 에 실제로 돌려 나온 것을 그대로 옮긴 것이다.

**과제**: 위 목록에서 문장을 하나씩 보며 **"이건 사람이 짠 규칙이 만든 문장인가,
AI 가 만든 문장인가"** 를 분류한다.

<details>
<summary>답 (진행자용)</summary>

- **판정 사유(`failure_detail`)는 전부 사람이 짠 규칙이 만든다.** AI 가 관여하지 않는다.
- **케이스 제목만** AI 가 다듬는다. 다만 오늘 실행은 `--backend mock` 이라 AI 를 안
  불렀고, 제목도 규칙 기반 원문 그대로다. 실행 끝에 뜨는 경고가 그 사실을 말한다:
  `케이스 제목 다듬기를 건너뛰었습니다`
- **여기서 "mock 이 뭐예요?" 가 나오면 잘 된 것이다.** "GPU 를 반납해서 지금은 진짜
  모델 대신 정답지를 읽고 있다. 6주차에 제대로 다룬다" 로 받아 두고 넘어간다.

</details>

**한 걸음 더** — 실패 사유 전문까지 읽고 싶으면:

```python
for c in r["cases"]:
    if c["verdict"] == "FAIL":
        print(c["case_id"])
        print("   ", c["failure_detail"])
        print()
```

## 두 사람이 막힐 만한 곳

| 막히는 곳 | 이렇게 받는다 |
|---|---|
| **"혼나면 통과" 가 안 와닿는다** | 일부러 틀린 답을 쓴 시험지를 낸 것. 선생님이 빨간 줄을 그으면 **채점이 제대로 되고 있다**는 뜻이다 |
| **왜 앱을 두 개나 만들었나** | 체온계를 믿으려면 열 있는 사람과 없는 사람을 둘 다 재 봐야 한다 |
| **"mock 이 뭐예요"** | GPU 를 반납해서 지금은 진짜 모델 대신 정답지를 읽는다. 6주차 |
| **S1·S2 같은 이름이 어렵다** | 오늘은 외우지 않아도 된다. "여섯 칸 중 파란 칸 둘" 만 기억하면 된다 |
| **터미널이 처음이라 무섭다** | 오늘 학생이 치는 명령은 `uv run python` 하나뿐이다. 나머지는 팀장 화면 |
