이 문서는 1차 대상 화면을 한 문서에 담는다. 화면마다 페이지를 새로 시작한다.

## 1. 화면 개요

| 항목 | 내용 |
|---|---|
| 화면 ID | login |
| 화면명 | 로그인 |
| 화면 경로 | /login |
| 설명 | 기존 회원이 이메일과 비밀번호를 입력해 서비스에 로그인하는 화면 |

## 2. UI 요소 정의

| 요소 ID | 유형 | 라벨 | 필수 | 입력 검증 규칙 | 에러 메시지 |
|---|---|---|---|---|---|
| email | 입력 | 이메일 | 필수 | 이메일 형식(@ 포함) | 올바른 이메일 형식을 입력하세요. |
| password | 입력 | 비밀번호 | 필수 | 8자 이상, 대문자 1자 이상, 특수문자 1자 이상 | 비밀번호는 8자 이상이며 대문자·특수문자를 각 1자 이상 포함해야 합니다. |
| login_btn | 버튼 | 로그인 | - | - | - |

### 2-1. 입력 검증 규칙 상세

**이메일**
- 필수 입력이다. 비어 있으면 에러 메시지를 노출한다.
- `@` 를 포함한 이메일 형식이어야 한다. 형식이 맞지 않으면 "올바른 이메일 형식을 입력하세요." 를 노출한다.

**비밀번호**
- 필수 입력이다. 비어 있으면 에러 메시지를 노출한다.
- 최소 길이는 8자다.
- 영문 대문자를 1자 이상 포함해야 한다.
- 특수문자를 1자 이상 포함해야 한다.
- 위 규칙 중 하나라도 위반하면 "비밀번호는 8자 이상이며 대문자·특수문자를 각 1자 이상 포함해야 합니다." 를 노출한다.

## 3. 성공 조건

이메일과 비밀번호가 모든 입력 검증 규칙을 만족하고 등록된 계정 정보와 일치하면,
`/dashboard` 로 이동하고 "환영합니다" 문구를 노출한다.

## 4. 실패 조건

| 상황 | 처리 |
|---|---|

| 이메일 형식이 올바르지 않음 | "올바른 이메일 형식을 입력하세요." 노출, 이동하지 않음 |
| 비밀번호 검증 규칙 위반 | "비밀번호는 8자 이상이며 대문자·특수문자를 각 1자 이상 포함해야 합니다." 노출, 이동하지 않음 |
| 등록되지 않은 계정 | "이메일 또는 비밀번호가 올바르지 않습니다." 노출, 이동하지 않음 |

## 화면 흐름 정의

화면 하나만으로는 확인할 수 없는 것이 있다. 회원가입으로 만든 계정으로 실제로
로그인이 되는지는 두 화면을 이어서 밟아야 알 수 있다.

| 흐름 ID | 화면 순서 | 이동 방법 |
|---|---|---|
| signup_link_to_login | signup → login | 로그인하러 가기 |
| signup_then_login | signup → login | - |

두 흐름은 같은 화면을 밟지만 확인하는 것이 다르다.

- `signup_link_to_login` 은 **화면을 잇는 요소**를 확인한다. 완료 화면의
  '로그인하러 가기' 를 눌러서 로그인 화면에 닿는지 본다.
- `signup_then_login` 은 **이어진 상태**를 확인한다. 주소로 직접 로그인 화면에 가서,
  가입에 쓴 계정으로 로그인이 되는지 본다.

각 화면의 성공 조건이 그 단계의 확인 기준이다. 중간 화면에서 성공 조건이 충족되지
않으면 그 화면에서 끊긴 것으로 본다.

이동 방법에 적은 요소를 눌러서 다음 화면으로 옮긴다. 그 요소가 없거나 엉뚱한 경로를
가리키면 흐름이 거기서 끊긴다. 이동 방법이 '-' 이면 주소로 직접 이동한다.
